# 공사현장 개편 v0.5.0 검증

날짜: 2026-10-09 (Asia/Seoul)

## 구현과 자동 검증

- 네이티브 Activity/Canvas HUD 및 OpenGL ES 2.0 실시간 메시. WebView를 사용하지 않음.
- 두 종류 로봇에 7색 재질, 평면 4열 대기열, 동일 열 앞쪽 선택과 상승, 기본 5개 활성 컨테이너.
- 공용 트럭 적재·탑승·출발·도착은 활성 컨테이너 해제와 독립적임. 20개 적재 기준, 마지막 부분 적재 차량도 출발.
- 새 JSON 레벨 200개: 초반 400개, 일반 1,024개 블록. 재현 가능한 생성기는 `scripts/generate-construction.mjs`.
- `node scripts/verify-native.mjs`: 실제 APK 자바 엔진 457개 assertion 통과. 기본 로봇만/게이지 보너스 사용 각각 200개 레벨 완주(400회). 최종 회수뿐 아니라 전체 자재의 트럭 적재와 빈 적재량도 확인.
- 앞쪽 선택·동일 열 상승·다른 열 유지, 타깃 중복 예약 방지, 두 단계 회수량, 트럭과 컨테이너의 독립성, 전체/부분 적재 차량 출발, 일시정지, 7번째 색 제거, 아이템 제한 및 비밀 터치 순서 검사.
- `node --test`: 기존 참조 엔진·데이터 회귀 테스트 213개 통과. 새 네이티브 레벨의 검증은 위 Java 테스트를 기준으로 함.
- `assembleDebug lintDebug --offline --no-daemon`: 성공. lint 오류 0개, 세로 화면·리소스 문자열·프로그램 방식 View 생성 등 경고 15개.
- `scripts/verify-native-apk.ps1`: JSON 레벨 200개, NativeGame/NativeScene DEX 클래스, HTML/JS/CSS 자산 0개, WebView 참조 0개 확인.

## 실제 기기

- Samsung SM-S948N, 화면 1440×3120에서 확인.
- v0.5.0/versionCode 7을 `adb install --user 0 -r`로 설치. 동일 applicationId와 개발 서명으로 기존 기록·코인·아이템·설정을 유지.
- 메인: 서로 다른 운반원/중장비 3D 구조, 큰 플레이 버튼과 아이콘 메뉴, 총 스테이지 수 없음.
- 일반 32×32 보드에서 그림 전체와 작은 입체 자재가 표시됨. 카메라 위쪽 잘림을 수정하고 블록 가로·세로 간격과 모서리 조명을 확인.
- 컨테이너를 선택했을 때 위쪽 작업 공간으로 이동, 같은 열 뒤쪽 카드 상승. 여러 로봇의 출격·운반, 짐이 실린 공용 트럭과 중장비 이동을 캡처.
- 일시정지의 재생/사운드/재시작/메인 2×2 아이콘 확인. 설정 제목 외에 숨겨진 모드의 안내나 스위치를 표시하지 않음.
- 설정 제목 7회 터치 시 `아이템 무제한 모드 On` 표시 및 SharedPreferences 저장. 재실행 후 `∞` 배지 유지.
- 무제한 상태에서 작업 공간 추가를 사용한 뒤 보유 아이템 수량 `[3, 2, 3, 3]` 유지 확인.
- 셔플·꺼내기 조작과 컬러 제거 선택 화면을 기기에서 확인. 같은 판에서 두 색을 연속 제거한 뒤에도 보유 수량 유지. 이후 같은 7회 터치로 `아이템 무제한 모드 Off` 알림과 저장을 확인하고 일반 메인 화면으로 복귀.
- 디버그 측정 표본: 보드 1,024개 및 작업 로봇 8기 상태에서 렌더링 루프 평균 약 12~16ms, GL 오류 0. 초기 메시 생성 프레임은 별도로 더 오래 걸림. 전체 기기군의 FPS 보장은 아님.
- 기기 확인용 `inspect_level` 인텐트는 debug 빌드에서만 사용. 해당 판은 진행·코인·기록을 저장하지 않음.

로컬 캡처는 `artifacts/redesign-*.png`에 저장하고 Git에서 제외함. 생성형 디자인 시안은 실제 기기 캡처와 구분하여 `docs/concepts/`에 보관.
