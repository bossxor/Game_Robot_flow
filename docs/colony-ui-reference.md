# Colony Flow UI 비율 적용

참고: 사용자가 제공한 `참고앱/Colony Flow.apk`, 패키지 `com.abi.colony.flow`, v1.0.76. 연결된 기기에 설치된 동일 버전의 전체 패키지에서 스테이지 474 화면과 컨테이너 선택 직후를 확인했다. 제공된 파일은 base APK이며 런타임·게임 자산은 기기의 별도 split APK에 있다.

목적은 UI 크기·배치·표현 방식 적용이다. 게임 테마는 기존 로봇과 공사현장으로 유지한다. 참고 APK와 기기 캡처는 로컬 자료이며 Git에서 제외한다.

## 화면에서 측정한 비율

1440×3120 기기 캡처를 기준으로 한 근사값이다. 다른 화면 비율에서는 보드가 잘리지 않도록 축소한다.

| 영역 | 참고 화면 | 적용 |
| --- | --- | --- |
| 보드 외곽 프레임 | 화면 가로 약 90% | 밝은 공사현장 프레임과 안쪽 단차 |
| 블록 그림 영역 | 화면 가로 약 76%, 거의 정면인 높은 시점 | 직교 카메라, 동일 간격의 촘촘한 자재 |
| 한 컨테이너 | 가로 약 12.5%, 정사각형 몸체와 두꺼운 밑면 | 논리 가로 384에서 48×48, 밑면 9 |
| 활성 컨테이너 | 대기 카드와 같은 크기, 위쪽 5자리 | 중앙 정렬, 동일 카드 크기, 기본 5개 제한 |
| 대기열 | 넓은 카드로 화면을 채우지 않고 중앙에 모음 | 기존 4열: 전체 가로 약 59%; 열 사이 12, 행 간격 62 |
| 숫자 | 큰 흰색 숫자, 진한 외곽선 | 중앙 숫자와 글자 외곽선, 긴 숫자는 자동 축소 |
| 선택 가능한 앞줄 | 밝은 테두리와 선명한 숫자 | 앞줄 테두리, 뒤쪽은 낮춘 밝기 |
| 선택·상승 | 카드가 활성 자리로 올라가며 뒤 카드가 당겨짐 | 220ms 이동, 대기열 위에 이동 카드를 그려 겹침 순서 보정 |
| 아이템 | 원형 버튼이 하단 패널 윗부분에 걸침 | 원형 그림 버튼 4개, 작은 수량 배지, 패널 위로 돌출 |
| 도착 지점 | 보드 아래 중앙, 활성 컨테이너보다 위 | 기존 공용 트럭을 같은 위치 관계로 배치 |

참고 앱의 스테이지 474는 5열 대기열이다. 기존 사용자 요청과 게임 데이터의 4열 규칙은 유지하고 각 카드의 폭·높이를 같은 기준으로 적용한다. 빈 활성 자리의 흰 판은 기존 요청대로 표시하지 않는다. 참고 앱의 연결 파이프·광고·하트·이벤트·구매 유도 흐름은 추가하지 않는다.

## 블록 밀도와 작업 시간

- 일반 보드를 32×32에서 48×48(2,304개)로 변경해 화면상의 한 블록을 더 작게 표시한다. 참고 스테이지의 정확한 논리 격자 개수는 확인하지 않았으며, 캡처에서 보이는 작은 셀 크기를 맞추기 위한 구현값이다.
- 튜토리얼 2개는 20×20을 유지한다.
- 일반 컨테이너 수량은 20~100개 범위의 기본 묶음과 남은 색 수량으로 생성한다. 같은 색 재고의 합은 보드 블록 수와 일치한다.
- 격자 확대에 따라 이동 속도와 동시 작업 로봇 수를 보정한다. 48칸 보드는 32칸 대비 이동량 1.5배, 컨테이너당 최대 12기. 화면 좌표 기준 이동 속도와 보행 모션 주기를 유지하기 위한 보정이다.
- 로봇 종류는 두 단계, 기본 1개/중장비 최대 8개 회수, 활성 컨테이너 5개, 트럭 적재량 20개 규칙은 유지한다.
- 이전에 요청한 기본 속도 2배 보정은 그대로 적용한다.
- 블록은 얇은 두께와 좁은 간격, 모서리 명암으로 표현한다. 구역별 GPU 버퍼를 만들고 제거된 구역만 갱신해 늘어난 자재의 업로드 부담을 줄인다.

## 수정 파일

- `GameLayout.java`: 컨테이너·대기열·하단 패널 기준 치수
- `NativeHud.java`: 카드 형태, 숫자, 테두리, 선택 모션, 아이템 배치
- `MainActivity.java`: 화면 영역 높이와 선택 불가 메시지
- `NativeScene.java`: 프레임, 카메라, 블록 표현, 트럭 위치, 구역 GPU 버퍼
- `NativeGame.java`: 큰 격자의 이동·동시 작업 수 보정
- `scripts/generate-construction.mjs`: 큰 그림 보드와 컨테이너 묶음 생성

초기 후속 수정 시에는 소스만 적용했다. 이후 사용자 요청에 따라 v0.6.0으로 빌드·ADB 설치하고 500개 레벨과 웹 화면 업데이트를 포함했다. 최신 설치·화면 확인 기록은 [v0.6.0 검증](v06-validation.md)을 따른다. 기존 `releases/RobotFlow-v0.5.0-native-3d-debug.apk`는 이전 32×32 버전으로 유지한다.
